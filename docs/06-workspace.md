# 工作区与文件工具

模型可以读写你选择的**一个目录**。这是整个应用里唯一能碰到"目录之外"的能力，
所以权限被拆成了三件事分别表达。

## 三个工具

定义在 `application/tools/workspaceToolRegistry.ts` 的 `DEFINITIONS`：

| 工具 | 参数 | 会改数据 | 上限 |
|---|---|---|---|
| `list_dir` | `path?`（省略=根目录） | 否 | 200 条 |
| `read_file` | `path` | 否 | 20000 字符（超出截断并**注明**） |
| `write_file` | `path`、`content` | **是** | —— |

`write_file` 会**自动创建缺失的中间目录**，所以"新建目录 + 写文件"一次调用就够。

**失败不是异常**：`run(call)` 从不抛错，它返回"给模型看的一句话 + `isError`"。
工具失败是对话的一部分 —— 模型需要知道"写失败了，因为没权限"，才能换个做法。
参数 JSON 残缺时会**拦住并说明原因**（最常见是单次输出上限把参数截断了），
而不是含糊地报"缺少参数"。

## 权限模型

| 动作 | 条件 |
|---|---|
| **读** | 选中了目录 + 浏览器对该句柄 `granted` |
| **写** | 上面两条 **且** `handleState === 'granted'` **且** `writeState === 'granted'` **且** `permission.allowEdit` |

写入授权必须来自**用户手势**：`WorkspaceApi.authorizeWrite()` 要在点击处理函数里
**同步地、先于任何 `await`** 调用 —— 浏览器只在手势的同一个任务里认这个请求。

开关是两级的：

```
全局默认（设置 → 工作区：allowEdit）
  ↑ 可被覆盖
会话覆盖（会话设置：三态 true / false / null=继承）
```

解析在 `domain/value-objects/workspace.ts: resolveWorkspacePermission`（纯函数，有单测）。
`writeFile` 是**唯一的写门禁**，未授权时返回 `FS_EDIT_DENIED` 并弹一条警报。

## 路径沙箱

`domain/rules/workspacePath.ts`：

- 只接受**相对路径**（如 `小说/第一章.txt`），不接受绝对路径、盘符、`..`；
- 归一化后拒绝：空、绝对、盘符、越界、含 NUL、层级过深（> 48）；
- `write_file` 的路径也会走同一套校验。

**沙箱的安全性不靠字符串前缀比较**，而是"交给句柄 API 解析 + 结构性不越界"：
即便路径写得再刁钻，最终的句柄解析也不会跑出选中目录。

## 句柄怎么存

浏览器的目录句柄不能序列化进 SQLite，所以：

```
IndexedDB（adapters/host/handleStore.ts）  ← 令牌 → FileSystemDirectoryHandle
SQLite（conversation.workspace_root）      ← 只存那个**令牌**
```

好处：数据库可以随便复制/备份，不会顺带泄露目录访问权。代价：换了浏览器配置之后
需要重新选择目录（浏览器也可能要求重新确认授权）—— 界面上的「重新授权」按钮就是干这个的。

## 系统提示词里的工作区说明

`workspaceToolRegistry.promptSection()` 会生成一段能力说明追加到系统提示词。它有两个要求：

1. **稳定内容在前、易变内容在后**（工具说明、路径规则在前；目录名、当前权限状态在后）——
   提示词缓存是"最长公共前缀"匹配，而这段位于消息数组最前面，
   中间插一个会变的东西会让它后面的全部内容每轮失效；
2. 讲清"为什么现在不能写"，要**讲到能照着做**的程度（去开开关 vs 去点授权是两件不同的事，
   混成一句"没权限"会让模型反复重试、让用户到处找）。
